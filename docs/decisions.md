# Decisions

- 2026-10-24: Flutter 3.35.7 pinned for reproducible scaffold generation; not a claim that it is the latest SDK.
- Linux initially supports UI and synthetic pose playback only. CameraX and Android Filament code cannot run unchanged on Linux. Desktop camera/3D tracking is separate future work.
- CI bootstraps absent platform runners from the pinned Flutter template. Custom native runners must be committed when native work begins. App code and pubspec already exist, so flutter create does not replace them.
- Linux packaging includes the whole Flutter bundle, not just the executable. Ubuntu 22.04 x86_64 is the initial CI baseline; other distributions require testing.
- No approved character or tracking model is included. No third-party model distribution rights are assumed.

- Rendering work lives in a committed local Flutter Android plugin, rather than generated app runners. The pinned runner template remains reproducible and does not overwrite custom native implementation.
- A generated original CC0 block humanoid unblocks development while waiting for the owner asset. Its simple identity bind axes are not assumed to hold for Mixamo.
- Filament 1.56.0 Android ModelViewer/FilamentAsset/Animator APIs checked against exact tagged source. Direct TransformManager writes precede updateBoneMatrices; clip playback is disabled.

- app/pubspec.lock recovered directly from the successful CI dependency resolution and committed with all hosted package checksums; no hand-invented dependency hashes.

- 0.3.0: User confirmed that the Android build had no camera and reported the GLB loader was not fixed. Camera was previously unimplemented, not a device configuration issue. Add independent M04/M05 camera proof while M03 visual acceptance remains open.
- GLB composition fix: use Filament's supported TextureView constructor, keep native library initialization scoped to the rig, resolve Flutter asset paths through FlutterAssets, validate GLB framing and provide reload/error stages. Root cause on the user's device is not proven until retested.
- Camera proof uses MediaPipe VIDEO mode on a dedicated synchronous analysis worker, rather than LIVE_STREAM callbacks. CameraX KEEP_ONLY_LATEST and bounded UI handoff avoid inference backlog and simplify image ownership. No camera data crosses Dart.
- MPImage.close() in MediaPipe 0.10.14 recycles its Bitmap. The displayed native camera frame therefore owns a separate copy; its matching landmarks use the same upright image coordinates. Display mirroring does not change anatomical landmark identities.
- The model is acquired at build time from Google's versioned float16/1 endpoint and bundled in the APK with its SHA-256 manifest. CI checks packaging and runtime code does not fetch models. Observed and pinned SHA-256: 59929e1d1ee95287735ddd833b19cf4ac46d29bc7afddbbf6753c459690d574a (CI run 40070114705).

- 0.4.0: Owner explicitly requested Linux camera support and a single directly runnable AppImage. This expands the earlier Android-only camera scope.
- Linux uses a bundled Python 3.10 MediaPipe 0.10.14/OpenCV worker. This is an intentional Linux exception to the Android rule against passing frames through Dart. Only local stdio is used; one credit requests one inference/image pair, with no unbounded frame queue or network listener.
- AppImage contains the Python interpreter, native dependencies, checksum-pinned model and Flutter assets. Host Python/pip is not required. Packaging tools linuxdeploy 1-alpha-20251107-1 and appimagetool 1.9.1 are checksum-pinned; appimagetool's own pinned runtime is reused to avoid a floating runtime download.
- Linux GLB preview parses/skinns the original small development asset in Dart/Canvas so it can be tested without Android Filament. It does not claim support for arbitrary GLBs, textures or large scenes. Actual mesh and inverse bind matrices replace the former stick diagram.
- Current CI and distribution baseline is Ubuntu 22.04 x86_64. AppImage packaging does not prove every Linux distribution or webcam works. FUSE-less temporary extraction is documented.

- 0.5.0 owner direction explicitly continues Linux retargeting development while device gates remain open, and pauses Android runners. Android CI uses literal false and Linux release no longer depends on or includes APK assets. No automatic Android re-enable after unit/CI success.
- Linux worker schema v2 adds world landmarks, UUID session IDs and monotonic sequence/timestamp metadata. Receipt time and source timestamps have separate clock purposes. Only one central adapter converts camera coordinates.
- Retargeting targets the original development rig. Calibration derives a neutral torso reference and per-bone corrections; globals are converted to parent-local normalized quaternions. Minimal swing preserves a neutral twist rather than pretending to recover axial twist from a direction.
- Explicit replay is synthetic, persistently labelled and never opens a camera. It supports repeatable calibration/solver/mesh tests and a focus-independent CI replay smoke. It is not model accuracy evidence.
- Full-body beta uses leg orientations and the original foot bounds to estimate a vertical display offset. Root X/Z and scales do not change. No precise foot IK or professional full-body accuracy claim is made.
- Owner requested finger support after the initial plan excluded it. Add it to the Linux 0.5.0 development rig using a separately bundled checksum-pinned Hand Landmarker, schema v3 wrist-anchored landmarks, and palm/finger skin joints. Existing Android runner pause remains in force. The generated rig is still the only supported character; synthetic articulation does not establish physical hand tracking quality.
- Owner next requested custom Mixamo FBX character support visible in the GLB view, then ZIP bundles with FBX and textures. Linux accepts FBX/GLB directly or a ZIP containing one model plus relative-path texture images; FBX conversion uses AppImage-bundled Assimp. The selected model is shared by the rig preview and camera avatar. Assimp output may contain partial per-vertex skin weights, so the viewer normalizes them and keeps up to four strongest influences. The Linux preview draws embedded base-color textures; one supplied Sketchfab ZIP passed conversion, GLB parsing and a raster-pixel texture check. Pose alignment, additional material channels, multiple skins and imported finger remapping remain unverified. Keep Android paused and do not infer webcam tracking quality from asset parsing.
- Owner requested live iPhone camera input using Iriun Webcam. The Linux tracker consumes the virtual `/dev/video*` device exposed by Iriun's desktop client, identifies its nodes in the camera picker, and falls back from OpenCV V4L2 to another available OpenCV backend. Iriun remains a user-installed dependency; Mimic does not implement Iriun's network protocol or bundle its driver. Automated device/backend tests are not physical camera proof.
- Calibration root cause: the solver cleared all accumulated neutral-pose samples on every invalid frame. To tolerate realistic intermittent landmark loss, calibration retains valid observations while gaps stay below 700 ms, then resets after sustained loss. It completes after 10 valid samples spanning 1.2 seconds, with progress and rejection reason visible in the UI/diagnostics. These are software tuning values awaiting physical webcam validation.
